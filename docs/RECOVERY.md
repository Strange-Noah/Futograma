# Futograma recovery

Use private Data platform mode verify_previous for entirely cloud-based download and integrity verification of current and previous. Production baseline promotion is not authorized during initial deployment.

For acceptance recovery dispatch recover_acceptance with a previous numeric acceptance run id. Only acceptance/<run-id> is selected; previous is restored and independently uploaded twice, both recovery copies are verified, stale writers rejected, production main rechecked. Release retention is dry-run only.

The reviewed cloud driver retains production recover, gated by owner enable, explicit handover, exact reviewed head and PROMOTE_PREVIOUS. Do not invoke it during deployment. Preserve current, previous, unresolved evidence and provenance; never force-push or delete local originals. All code, data, credentials and instructions live in GitHub after migration; the original workstation is not a runtime or recovery service.
