# Managed roster and raw browser

A club-managed roster is not a season appearance union or contract-ownership list. Verified FIRST_TEAM, injury-retained and LOAN_IN events can include a player. A verified LOAN_OUT/TRANSFERRED_OUT blocks stale ownership profiles until explicit dated return/signing evidence. Unknown is excluded by default. Historical matches and affiliations are never deleted. Current official squad cards are observed snapshots, not fabricated historical contract dates; the legal senior register is parsed only inside the exact club heading, excluding U21 contract/scholar lists.

The website has Team → Player → Match records navigation, a six-club sidebar, raw dates/competition/opponent/represented club/minutes/source status and a separately labeled historical/unknown toggle. No workload index, rolling chart or prediction is shown. Zero, null and pending selection are different states. Pending team fixtures do not assert that every club-managed player was selected.

The new match_retry_queue and append-only match_retry_history live inside the existing SQLite architecture. Only justified temporary incompleteness or transient network errors use normal retries. Empty competition requires full-time, ordered-team/date agreement and independently recognized catalog competition plus an actually empty detail field; None is never assigned a competition. Identity, unknown nonempty competition, parser/schema and integrity problems remain visible, quarantined or escalated.

Retry policy is in ops/cloud/retry-policy.json. First 24h waits for the next daily slot; 24–72h retries daily; 72h–7d continues and may try previously corroborated permitted alternatives, never a guessed URL. Due queue records bypass the regular 72h cutoff. After the configured maximum age, human review is required. If completion time is unavailable, age uses the first persisted observation and states that limitation; kickoff+90 is not invented as a completion timestamp. Old failed task metadata is not silently discarded. A successful retry resolves a temporary item and keeps history; replay tokens are idempotent. A later unapproved success cannot silently clear a quarantined identity conflict.

Phase-two tests and proposed management corrections use acceptance/phase2-data only. The preview site labels that acceptance dataset. Production current.json, match facts and legacy membership rows stay unchanged; ingestion remains false and authority handover unconfirmed. Migration of accepted membership proposals to production requires separate approval.
